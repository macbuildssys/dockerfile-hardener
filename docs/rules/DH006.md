# DH006 — SecretsInEnv

**Severity:** 🔴 CRITICAL
**Auto-fix:** ✗ No
**Tags:** CIS-DI-0010, OWASP-A02, Docker-Hardening, Secrets

---

## What this rule checks

`ENV` and `ARG` instructions must not contain credentials, tokens, API keys,
or any other sensitive values. The rule matches variable names containing
fragments such as:

`password`, `passwd`, `secret`, `api_key`, `token`, `auth`, `credential`,
`jwt`, `private_key`, `access_key`, `database_url`, `connection_string`,
`aws_secret`, `aws_access`, `github_token`, and others.

Two severity levels are used:

- **CRITICAL** — the variable name matches AND the value looks like a real
  secret (non-empty, not a placeholder like `CHANGE_ME`).
- **MEDIUM** — the variable name matches but the value is empty or a
  placeholder. The structure is risky even if no value is currently set.

---

## Why it matters

Secrets placed in `ENV` instructions are:

1. **Stored in every image layer** — they persist in the layer even if
   a subsequent instruction overwrites or deletes them.
2. **Visible in `docker history`** — anyone who can pull the image can run
   `docker history --no-trunc <image>` and read the value.
3. **Exposed in `docker inspect`** — the full environment of a running
   container is visible to anyone with Docker socket access.
4. **Committed to version control** — Dockerfiles are typically in git;
   a hardcoded secret in a `FROM`/`ENV` line will be in the repository
   history permanently.

`ARG` values with defaults are stored in the image manifest and are
similarly readable via `docker history`.

## Failing examples

```dockerfile
ENV DATABASE_PASSWORD=supersecret123
ENV API_KEY=sk-abc123xyz
ENV AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
ARG SECRET_TOKEN=my-default-secret
```

---

## Passing examples

**Pass at runtime — never bake in:**
```bash
docker run --env DATABASE_PASSWORD=secret myimage
# or
docker run --env-file .env myimage
```

**Docker secrets (Swarm):**
```dockerfile
# Mount a secret at runtime — never stored in the image
RUN --mount=type=secret,id=db_password \
    cat /run/secrets/db_password | myapp --configure
```

**BuildKit secret mounts (build time):**
```dockerfile
RUN --mount=type=secret,id=npm_token \
    npm config set //registry.npmjs.org/:_authToken=$(cat /run/secrets/npm_token) \
    && npm install
```

**Empty placeholder (MEDIUM, not CRITICAL):**
```dockerfile
ENV DATABASE_PASSWORD=
# Value injected at runtime via --env
```
