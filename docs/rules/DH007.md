# DH007 — AddInstruction

**Severity:** 🟡 MEDIUM (local file); 🟠 HIGH (remote URL)
**Auto-fix:** ✔ Yes (local file and tar cases)
**Tags:** CIS-DI-0009, Docker-Best-Practice, Docker-Hardening

---

## What this rule checks

`ADD` instructions are flagged in three cases:

| Case | Severity | Fixable |
|---|---|---|
| Local file copy (`ADD app.py /app/`) | MEDIUM | ✔ (replace with COPY) |
| Tar archive (`ADD app.tar.gz /app/`) | INFO | ✔ (replace with COPY + RUN tar) |
| Remote URL (`ADD https://...`) | HIGH | ✗ |

---

## Why it matters

`ADD` has two behaviours that `COPY` does not:

**1. Remote URL fetching** — `ADD https://example.com/setup.sh /tmp/` makes
a network request at build time. The fetched content is not verified
(no checksum, no signature). A compromised or man-in-the-middled URL
silently poisons your build. Use `RUN curl` with an explicit checksum
verification instead.

**2. Tar auto-extraction** — `ADD archive.tar.gz /app/` automatically
extracts the archive. This is implicit and surprising; `COPY` + `RUN tar`
is explicit and auditable.

For plain local file copies, `ADD` and `COPY` behave identically — but
`ADD` carries the risk of someone later changing the source to a URL
without realising the security implications. `COPY` is always the safer,
more explicit choice for local files.

---

## Failing examples

```dockerfile
ADD app.py /app/app.py                         # MEDIUM — use COPY
ADD app.tar.gz /app/                           # INFO — use COPY + tar
ADD https://example.com/setup.sh /tmp/         # HIGH — unverified fetch
```

---

## Passing examples

```dockerfile
# Local file — use COPY
COPY app.py /app/app.py

# Archive — explicit extraction
COPY app.tar.gz /tmp/
RUN tar xzf /tmp/app.tar.gz -C /app/ && rm /tmp/app.tar.gz

# Remote file — use curl with checksum
RUN curl -fsSL https://example.com/tool-1.2.3-linux-amd64.tar.gz \
        -o /tmp/tool.tar.gz \
    && echo "abc123...  /tmp/tool.tar.gz" | sha256sum -c \
    && tar xzf /tmp/tool.tar.gz -C /usr/local/bin/ \
    && rm /tmp/tool.tar.gz
```

---

## Auto-fix behaviour

For local file `ADD` instructions, `--fix` replaces `ADD` with `COPY` in-place.
Remote URL and tar cases are not auto-fixed because the replacement requires
structural changes (adding a checksum verification step).
