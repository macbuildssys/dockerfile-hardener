# DH010 — FileOwnership

**Severity:** ⚪ INFO
**Auto-fix:** ✔ Yes
**Tags:** Docker-Hardening, Least-Privilege

---

## What this rule checks

When a stage sets a non-root `USER`, any `COPY` or `ADD` instructions in that
stage that do not use `--chown` are flagged. Files copied without `--chown`
are owned by root regardless of which user the container runs as.

This rule only fires when:
1. A non-root `USER` is set in the stage, AND
2. A `COPY` or `ADD` instruction is present without `--chown`.

If no `USER` is set, DH001 covers the issue. If the user is root, file
ownership is not the concern.

---

## Why it matters

If the application runs as `nonroot` but its files are owned by root, the
process may be unable to read its own configuration, write to its own data
directory, or execute its own binaries depending on the file permissions.

Developers often work around this with broad `chmod 777` or by adding
the non-root user to the root group — both are worse than simply setting
`--chown` correctly.

---

## Failing example

```dockerfile
FROM python:3.12.3-slim
RUN useradd --uid 1000 appuser
COPY app/ /app/          # owned by root
USER appuser
CMD ["python", "-m", "app"]
# appuser may not be able to read /app/ depending on permissions
```

---

## Passing example

```dockerfile
FROM python:3.12.3-slim
RUN useradd --uid 1000 appuser
COPY --chown=appuser:appuser app/ /app/
USER appuser
CMD ["python", "-m", "app"]
```

Multi-stage with `--chown`:
```dockerfile
FROM python:3.12.3-slim AS builder
# ... build steps ...

FROM python:3.12.3-slim
RUN useradd --uid 65532 nonroot
COPY --from=builder --chown=nonroot:nonroot /install /usr/local
COPY --chown=nonroot:nonroot app/ /app/
USER nonroot
CMD ["python", "-m", "app"]
```

---

## Auto-fix behaviour

`--fix` inserts `--chown=<user>:<user>` into the affected `COPY`/`ADD`
instruction, using the username from the `USER` instruction. Review the
result — ensure the user and group names match what is actually created
in your image.
