# DH009 — PrivilegedPort

**Severity:** 🔵 LOW
**Auto-fix:** ✗ No
**Tags:** Docker-Hardening, Least-Privilege

---

## What this rule checks

`EXPOSE` instructions that declare a port below 1024 are flagged. Ports in
the range 1–1023 are "privileged ports" on Linux and require `CAP_NET_BIND_SERVICE`
or root access to bind.

---

## Why it matters

Binding to a privileged port inside a container requires either:
- Running the container as root (violates DH001), or
- Granting `CAP_NET_BIND_SERVICE` (widens the capability surface).

Both are unnecessary. The standard solution is to run the application on a
port >= 1024 inside the container and use Docker's port mapping to expose
it externally on port 80 or 443:

```bash
docker run -p 80:8080 myimage
```

This keeps the container process unprivileged while external clients still
connect to standard ports.

---

## Failing example

```dockerfile
EXPOSE 80
EXPOSE 443
EXPOSE 22
```

---

## Passing example

```dockerfile
EXPOSE 8080    # application listens here (unprivileged)
# External mapping: docker run -p 80:8080 or via ingress controller
```

---

## Note on EXPOSE semantics

`EXPOSE` is documentation — it does not actually publish the port. The port
is only accessible from outside if `-p` or `-P` is passed to `docker run`,
or if configured via Docker Compose or a Kubernetes Service. This rule flags
the intent declared in `EXPOSE` because it indicates the application is
designed to bind to a privileged port.
