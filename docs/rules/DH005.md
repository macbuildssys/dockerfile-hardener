# DH005 — NoHealthcheck

**Severity:** 🔵 LOW
**Auto-fix:** ✔ Yes
**Tags:** Docker-Best-Practice, Reliability

---

## What this rule checks

The final build stage must contain a `HEALTHCHECK` instruction. Without it,
Docker has no mechanism to determine whether the container is actually
functioning — only that the process is running.

---

## Why it matters

A container can be running (from the OS perspective) while the application
inside it is completely broken — stuck in a deadlock, unable to connect to
its database, or serving 500 errors on every request.

Without a `HEALTHCHECK`:
- Docker marks the container as `Up` regardless of application state.
- Orchestrators like Docker Swarm cannot distinguish a healthy container
  from a broken one and will not restart it automatically.
- Alerting systems that rely on container status will not fire.

Note: Kubernetes uses its own liveness and readiness probes rather than
the Docker `HEALTHCHECK`. However, the instruction is still valuable for
local development, Docker Compose deployments, and Docker Swarm, and it
serves as self-documenting intent about what "healthy" means for the image.

---

## Failing example

```dockerfile
FROM python:3.12.3-slim
COPY app/ /app/
USER nonroot
CMD ["python", "-m", "app"]
# No HEALTHCHECK — Docker cannot verify the app is responding
```

---

## Passing examples

HTTP service:
```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD wget -qO- http://localhost:8080/health || exit 1
```

Using curl:
```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD curl -f http://localhost:8080/health || exit 1
```

TCP port check (no HTTP endpoint):
```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD nc -z localhost 5432 || exit 1
```

Disable healthcheck explicitly (for base images):
```dockerfile
HEALTHCHECK NONE
```

## Auto-fix behaviour

When `--fix` is run, the following template is inserted before `CMD`/`ENTRYPOINT`:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=5s --retries=3 \
    CMD wget -qO- http://localhost:8080/health || exit 1
```

Review the generated instruction and adjust the port, path, and command to
match your application.

---

## Options reference

| Option | Default | Meaning |
|---|---|---|
| `--interval` | 30s | Time between checks |
| `--timeout` | 30s | Time before a check is considered failed |
| `--start-period` | 0s | Grace period during container startup |
| `--retries` | 3 | Consecutive failures before marking unhealthy |
